## Problem and current behavior

Master (after P1) already has one atomic commit stream per CRTC: scene flips, direct scanout, composed unflip and `NONBLOCK | PAGE_FLIP_EVENT` cursor-only commits, at most one commit in flight per CRTC, and every event-producing commit now carries a nonzero kernel cookie and is retired by it. Of the cursor, that stream carries only **positions**:

- `CursorPlanePosition` (`drm/atomic.rs:199`) holds `CRTC_X`/`CRTC_Y` of a plane that is already visible. `cursor_plane_atomic_positions_for_outputs` (`platform/cursor.rs:363`) offers it to every producer; `submit_atomic_cursor_move_for_output` (`platform/cursor.rs:477`) sends it cursor-only. A device qualifies only when every active CRTC has a cursor plane exposing `CRTC_X` and `CRTC_Y` (`CursorPlane::supports_atomic_positions`, `kms/cursor_plane.rs:584`).
- Image, hotspot, show and hide still use the **legacy** `set_cursor2` ioctl (`CursorPlane::show`/`hide`, `kms/cursor_plane.rs:683`/`730`), outside the atomic stream, with no commit identity. The scene sequences them with `ShowOnRetire`/`HideOnRetire` (`yserver-render` `scene/cursor.rs`, `scene/tick.rs`), whose retirement (`apply_cursor_transition_on_retire`, `scene/cursor.rs:544`, called from `scene/flip.rs:218` and `scene/cursor.rs:112`; `ShowOnRetire` is built in `scene/tick.rs:761`) calls `OutputSink::cursor_plane_mut().{upload,show,hide}`.
- All outputs of a device share **one** dumb buffer. `CursorPlane::upload_image` (`kms/cursor_plane.rs:646`) clears and rewrites that buffer in place, so an animation frame or a new cursor overwrites pixels the plane may still be scanning, and a hotspot-only change has no buffer identity at all.
- There is no hotspot client capability. On paravirtualized drivers (virtio_gpu, vmwgfx, qxl, vboxvideo) the kernel then hides the cursor plane from the plane list (`drm_plane.c`: cursor planes are skipped unless `DRM_CLIENT_CAP_CURSOR_PLANE_HOTSPOT` was accepted), so master sees no cursor plane and takes the optimistic legacy probe.
- A cursor-only commit in flight is retired by any flip event on its CRTC: `retire_atomic_cursor_commit_for_output` (`platform/cursor.rs:564`), called from `backend_scanout_on_page_flip_ready` after P1's attribution (`scanout.rs:2201,2229,2290`), ignores the matched commit ID that P1 now provides.

P2 moves the cursor image, hotspot, attach and detach onto that same stream as **full-state cursor-plane properties**, backed by a per-device pool of full-capacity sprite framebuffers whose reuse is tied to commit-ID-attributed events. Master's legacy path remains complete and is selected whenever the atomic path is not provably usable.

## Global constraints

- Everything on the legacy path is unchanged when the device does not qualify (rule R3). Master's `set_cursor2`/`move_cursor` executors, hide-recovery and transient-fallback state, and the software-cursor policy stay in place and keep their tests.
- Devices with no universal cursor plane (Apple DCP / Asahi) keep the optimistic legacy probe and the permanent software-cursor latch on `ENXIO`/`ENODEV`/`EOPNOTSUPP` exactly as today.
- Preserve Linux glibc, Linux musl and FreeBSD ioctl request typing; the hotspot client capability uses the portable pattern already used by P1 (`as _` cast of an `ioctl_num_type`), never `libc::Ioctl`.
- No new `YSERVER_*` behavior environment variables; no `cfg(test)` branches inside production function bodies (test-only items and fields are allowed when nothing reads them in production).
- Respect `tools/check-layout.sh`: 5,000-line code and 6,000-line test ceilings, `yserver-render` free of drm/gbm/input/udev/`yserver-core`, `backend/portable` free of KMS and platform names. Run it unmodified: the atomic-only cursor guard it gains in the reference belongs to P5.
- Keep `yserver-render` independent of the KMS stack: shared scene interfaces gain only `CursorUploadOutcome`, a `deferred` flag and hotspot-aware image identity (R19), never DRM types.
- Do not pull any maintainer finding or any P3-P5 behavior forward (see Non-goals).

## Terms

- **Cursor state path**: per device, decided once when the `CursorPlane` is constructed from static facts and never changed afterwards: `CursorStatePath::Atomic` (this spec) or `CursorStatePath::Legacy` (master, including its position-only atomic subpath).
- **Applied state**: what the last *accepted* cursor-carrying commit set on a CRTC's cursor plane (`Option<CursorBinding>`), plus `valid`, whether that record is trusted to describe the kernel.
- **Intent**: the cursor plane state one `show` or `hide` call wants (`Some(binding)` or detached). It is transient: P2 keeps no queued intent. **Prepared commit**: the property delta between that intent and the applied state.
- **Lease**: a staged sprite framebuffer identity `(slot, version, hot_x, hot_y)`. **User**: one CRTC's claim on a sprite framebuffer, in three roles: *reserved* (request built, not yet accepted), *accepted* (applied, or in flight), counted per CRTC. Every user has exactly one **release owner** (R10, R22, R23).

## Rules

### Capabilities and eligibility

**R1 — Hotspot capability and driver facts at KMS open.** `Device::open` sets, once each, `DRM_CLIENT_CAP_UNIVERSAL_PLANES`, then `DRM_CLIENT_CAP_ATOMIC` (negotiation *replaces* master's `enable_atomic_capabilities`, keeping its warning texts, so no capability is requested twice), then `DRM_CLIENT_CAP_CURSOR_PLANE_HOTSPOT` (value 6), then reads the DRM driver name, then runs P1's `DRM_CAP_CRTC_IN_VBLANK_EVENT` check, all before any plane enumeration. The whole post-open sequence is one function taking a `DeviceControl`, called by `Device::open`, so its order and count are testable. The result is `CursorDeviceCaps { hotspot_cap_accepted: bool, driver_name: Option<String> }`. A rejection of the hotspot capability is normal on physical drivers (`EOPNOTSUPP`): debug log, cached `false`. A failed driver-name query is a warning and caches `None`. Definitions: *paravirtualized* means the name is exactly one of `virtio_gpu`, `vmwgfx`, `qxl`, `vboxvideo` (the drivers that set `DRIVER_CURSOR_HOTSPOT` in the kernel); *unknown* means only that the name query failed, and is treated as needing hotspot support (conservative); no other name is ever demoted (`msm`, `xe`, `i915`, `amdgpu`, `nouveau`, `nvidia-drm`, `apple` and any case or suffix variant of the paravirtualized names are physical). `CursorDeviceCaps::requires_hotspot_support()` is true for paravirtualized and unknown. "No caps were negotiated" (render node, inherited fd, probe before wiring) is `cursor_caps() == None`, a separate fact with its own Legacy reason (R3). `Device::open` serves both `kms/outputs.rs:308` and the candidate probe `platform/drm.rs:181`; the probe fd negotiates too, which is harmless. P2a implements the sequence with the cursor step absent; P2b Task 5 adds the hotspot and driver-name step, so no device requests the capability before the path that uses it exists.

**R2 — Discovery keeps the property handles.** For each cursor-type plane, discovery records `possible_crtcs` and the handle of every property by name. `CursorPlaneProperties` collects `FB_ID`, `CRTC_ID`, `CRTC_X`, `CRTC_Y`, `CRTC_W`, `CRTC_H`, `SRC_X`, `SRC_Y`, `SRC_W`, `SRC_H` (required) and `HOTSPOT_X`, `HOTSPOT_Y` (optional). The CRTC-to-plane matching is master's #246 maximum matching with exclusive-plane preference, unchanged and computed over all cursor planes (not filtered by properties).

**R3 — Path decision: per device, once, static.** The path is decided when the `CursorPlane` is constructed, from facts that cannot change during its lifetime (plane presence, discovered properties, the assignment computed then, the caps captured then), stored on the plane, and never recomputed by a topology refresh. The plane captures `CursorDeviceCaps` itself at construction (production: `device.cursor_caps().cloned()`; tests: the snapshot); the decision reads only that stored copy. `Atomic` requires, in this order: at least one cursor plane is assigned; caps were negotiated (`Some`); every assigned plane exposes all ten required properties; and if `requires_hotspot_support()` then the capability was accepted and every assigned plane exposes `HOTSPOT_X` and `HOTSPOT_Y`. Otherwise `Legacy` with a reason (`no-cursor-plane`, `no-device-caps`, `missing-property:<NAME>`, `hotspot-support-missing`), which is exactly master's behavior (position-only atomic commits where `supports_atomic_positions`, legacy ioctls for the rest). The decision is logged once at install (`render cursor: device <key> cursor_state_path=<atomic|legacy> reason=<...>`). A CRTC that has no assigned plane stays master's separate availability gate (`topology_blocked`, software cursor for the device), which does not change the path: the scene's own `HideOnRetire` detaches an applied binding through the path's own hide. A device never mixes paths across CRTCs. Until P2b Task 5 wires the cursor step of R1, production devices have `cursor_caps() == None` and therefore decide `Legacy/no-device-caps`.

**R4 — No cursor plane, no atomic path.** A device with zero cursor planes is `Legacy` with no explicit plane assignment (master's optimistic probe) and Apple DCP keeps latching software on `ENXIO`.

### Sprite pool

**R5 — Full-capacity ARGB framebuffers.** Each device with the `Atomic` path owns a `SpritePool`. Every buffer is a dumb buffer of exactly `DRM_CAP_CURSOR_WIDTH` x `DRM_CAP_CURSOR_HEIGHT` pixels (master's 64x64 fallback only when the query fails or reports less than 64), ARGB8888, registered with `AddFB2`. The image occupies the top-left corner; every other mapped byte, including per-row pitch padding, is zero before the image is written, on every write. The pool starts with two buffers and grows to `max(2, active_crtcs + 1)`.

**R6 — Allocation is all-or-nothing.** Creating a buffer acquires, in order, the dumb handle, the mapping, the framebuffer; a failure releases only what was acquired, in reverse order, preserving both the original and any cleanup error. If the second initial buffer fails, the first is released. A failed or `WouldBlock` allocation or write publishes no lease, leaves the previous candidate and applied state untouched, and keeps the wanted image so a later pass retries it.

**R7 — Sprite identity includes the hotspot.** A lease is `(version, hot_x, hot_y)` plus geometry. Staging the same version with a different hotspot allocates and writes a different buffer (virtio forwards the hotspot only on a framebuffer change). Identity lookup covers every slot whose recorded `(version, hot_x, hot_y)` matches, not only the candidate: staging an identity that another slot already holds reuses that slot (it becomes the candidate) without a write or an allocation; a slot is rewritten only when it has no user and no reservation.

**R8 — Pressure defers, never overwrites.** When no buffer has zero users and zero reservations and the pool is at its maximum, staging returns `Deferred`: only the newest wanted image is retained (older pending images are dropped), no live buffer is rewritten, and nothing is reported as a driver rejection or disqualifies the hardware path. `Deferred` makes the scene retry through its existing `force_show_retry_version` repaint (R19).

**R9 — Oversize cursors.** An image larger than the buffer capacity is rejected with `InvalidInput` and `CursorPlaneSink::fits` is false before any upload, exactly as master (`cursor_dimensions_fit`). A byte length other than `width * height * 4` is rejected with `InvalidInput` without touching a buffer.

### Lease lifetime and commit identity

**R10 — Release only at the replacing event or a successful blocking detach.** A sprite framebuffer is rewritten or removed only when it has zero users and zero reservations. The previous binding's user is released only when the event of the commit that *replaced* it is attributed (R11), never at acceptance (the hardware may still read it until that event). The only other release point is R22 (a successful blocking detach, which returns after the hardware stopped scanning). A framebuffer shared by several CRTCs keeps one user per CRTC and survives until the last of them is released.

**R11 — Cursor commits are retired by commit ID.** Every cursor-only commit of the `Atomic` path is submitted through `AtomicCommitSink::submit_with_commit_id` and its in-flight record stores the accepted ID. The record is retired, and its prior lease released, only by an event whose P1-matched ID equals the stored ID. An absent ID, an unmatched ID, a duplicate, a stale or a wrong-CRTC/wrong-device event retires nothing (through `Backend` the observable guarantee for an explicit wrong cookie is P1's filter, `scanout.rs:2198,2226`, which drops it before cursor retirement; a zero cookie is attributed by P1's FIFO to the oldest pending entry and so retires the pending replacement correctly and exactly once; the local equality check is covered by a boundary test). The fixture's delivered-completion set uses `(device_fd, crtc, commit_id)`: P1 allocates IDs independently per device, and a grouped commit uses the same ID for each target CRTC. `Legacy` in-flight records keep master's membership retirement.

**R12 — One commit in flight per CRTC.** A cursor-only commit is not submitted while one is in flight, and cursor work waits behind an in-flight scene or direct commit on the same CRTC (`EBUSY` is the existing wait-for-next-event signal, consumes no lease and creates no in-flight record or event obligation). Retirement of a CRTC's event clears its wait mark.

**R13 — Reservations bracket submission.** Before `submit`, the new lease is *reserved* (one reservation per CRTC). On success it becomes an *accepted* user atomically with publishing the applied state and the in-flight record; on any failure the reservation is rejected and nothing else changes. Acceptance validates the whole transaction before transferring any lease, so a lost reservation fails closed.

**R14 — Rejection keeps master's policy but not its executor.** A cursor-only commit refused for a cursor cause (`take_last_cursor_rejection`), or a scene/direct commit refused for its position fields, is settled with master's policy (clear the cached position, transient software fallback `note_einval`, motion-led hide recovery with its 3-attempt permanent latch) but on the Atomic path the hide that rolls the cursor back is a **blocking atomic detach of the plane the accepted state names** (`applied.properties.plane`: `FB_ID = 0`, `CRTC_ID = 0`, no `NONBLOCK`, no event), never the legacy `set_cursor2(None)`, which acts on `crtc->cursor`, a plane that may differ from the assigned one, and is unsynchronized with scanout. On success the applied state becomes detached (`valid = true`) and the former binding's user is released (R22 release point); on failure `applied` and every lease are kept, `valid = false`, and master's `CursorHideRecovery` applies. Every hide outcome on the Atomic path, including a successful motion-led recovery hide and the 3-attempt latch, sets `applied`/`valid` to what the kernel holds; a latched device keeps its still-bound lease, whose release owner is any later successful detach (R22) or, never, in which case R15 leaks it visibly. Qualification keys, retry-per-key, explicit-detach `DetachPending`/`RetainHardware` states, cursor-only retry and EBUSY/EINVAL attribution changes are P5.

**R15 — Teardown never frees a used framebuffer.** Dropping a `SpritePool` (or its device) forgets, without `RMFB` or dumb destruction, every buffer that still has a user or reservation. Buffers with no users are released through the normal ordered path. The cursor ledger therefore reports a leak only for ownership that was genuinely never settled, never a freed live framebuffer.

### State and commit assembly

**R16 — Diff against accepted state.** A commit carries only the cursor properties that differ from the applied state, with these exact outcomes: *attach* (no applied binding, or `valid == false`): `FB_ID`, `CRTC_ID`, `CRTC_X`, `CRTC_Y`, `SRC_X = 0`, `SRC_Y = 0`, `SRC_W = capacity_width << 16`, `SRC_H = capacity_height << 16`, `CRTC_W = capacity_width`, `CRTC_H = capacity_height`, and `HOTSPOT_X`/`HOTSPOT_Y` when the plane exposes them; *replace* (applied binding, new lease): `FB_ID`, plus `CRTC_X`/`CRTC_Y`/`HOTSPOT_*` only if they differ; *move*: only the differing `CRTC_X`/`CRTC_Y`; *detach*: `FB_ID = 0` and `CRTC_ID = 0` (only when something is applied or `valid == false`); *no change*: no request. `CRTC_X`/`CRTC_Y` are signed (`i64` cast to `u64`) CRTC-local pointer minus hotspot. When a `show` or `hide` call's intent equals the applied state it returns success with no ioctl, no in-flight record and no event obligation. **Position invariant:** after any pointer motion the cached latest position equals the current pointer position (computed with the applied hotspot), and a pending move exists if and only if the latest differs from the applied position; a motion equal to the applied position therefore *removes* any existing pending move and updates the latest, without creating a request, event obligation or wakeup. After an accepted `show`, latest equals applied and there is no pending move (no redundant cursor-only commit follows an attach or replace).

**R17 — Every cursor field is attribution-tagged.** Every property added for the cursor, including all full-state fields, is added through `AtomicCommitRequest::add_cursor_property`, so the existing scene-with-cursor `TEST_ONLY` re-test strips all of them and cursor-only failures are recognised as cursor-caused. Async (tearing) commits carry no cursor property of any kind, as today. In P2 no scene-with-cursor commit carries a full-state field (R20), so the tagging is a boundary guarantee for P3; cursor-only failures already blame the cursor by kind.

**R18 — One accessor for "hardware cursor bound".** Every predicate meaning "the hardware cursor is bound on this CRTC" goes through one accessor, `KmsCursorState::hw_bound_on(crtc)`: on the Atomic path `crtc_states[crtc].applied.is_some()`, on the Legacy path master's `plane.is_visible_on(crtc)`. No Atomic-path branch calls `is_visible_on` directly. This covers every master site (`platform/cursor.rs:383,410,504,1143,1281,1328,1512,1558`): the position carriers, `has_eligible_atomic_cursor_move`, the cursor-only submit gate, motion and hide recovery, `cursor_crtc_membership_dirty`, `cursor_plane_visible_for_output`, `cursor_plane_hide_all` and `rearm_cursor`. The legacy `visible` map is neither read nor written on the Atomic path.

### Scene seam

**R19 — The scene retries pool pressure and EBUSY by itself.** `CursorPlaneSink::upload` returns `CursorUploadOutcome::{Ready, Deferred}` and takes the hotspot; `uploaded_image_matches(output, version, hot_x, hot_y)` replaces `uploaded_version`; `CursorShowFailure` gains `deferred: bool`. On `Deferred` the scene keeps its retained mode, records `force_show_retry_version` and forces a repaint (`CursorTransitionResult::Deferred`), so the existing retirement path retries without new scheduling. The `Legacy` sink implementations return `Ready` immediately and compare version only, preserving master's results exactly. The scene's branch for a missing matching entry (`no matching entry bytes`) keeps master's resolution (`resolve_failed_cursor_upload`) on every path, so Legacy behavior is unchanged; only an `upload` that returns `Deferred` or a `show` that reports `deferred` produces `CursorTransitionResult::Deferred`.

### Producers on the existing stream

**R20 — Where each change travels.** Attach, detach, image/hotspot replacement go through the `show`/`hide` sink adapters as one cursor-only commit each, at the same moments master issues legacy ioctls (scene retirement `ShowOnRetire`/`HideOnRetire`, direct-scanout hooks, resume rearm, lifecycle hide). Shared, copied, direct and composed-unflip commits continue to carry exactly the latest cached position of the applied binding, `CRTC_X`/`CRTC_Y` only (master carries it on every such commit, not only on change), and nothing else; they never carry `FB_ID`, `CRTC_ID`, hotspot or geometry in P2 and never touch a lease. A position is computed from the *applied* binding's hotspot, so a staged-but-unapplied replacement cannot shift the plane before its own commit. Accepting a position-carrying commit updates the applied `x`/`y`, so later diffs stay exact.

**R21 — Deferred work retries through the scene; positions stay the only queued cursor work.** A `show` or `hide` that cannot be submitted now (a commit is in flight on the CRTC, `EBUSY`, no free sprite, no prepared sprite) is not queued by the platform. It reports `deferred` (or `Deferred` for staging), keeps the previous accepted binding authoritative, and the scene's forced repaint (R19) calls it again with fresh values at the next retirement. The idle and held-direct cursor lanes, `scene_wants_compose` and the next-wakeup computation therefore keep master's definition of cursor work (a pending position that is eligible: visible, not in flight, not waiting on a flip, available). A position equal to the applied position creates no pending work and wakes nothing (R16).

### Lifecycle minimum

**R22 — Blocking detach before every blocking disable; settle every lease owner.** Before each blocking CRTC disable (VT suspend `hide_all`, DPMS off, connector disable and hot-unplug, shutdown `disable_output`), the platform submits a blocking cursor-plane detach (`FB_ID = 0`, `CRTC_ID = 0`, no `NONBLOCK`, no `PAGE_FLIP_EVENT`, no event obligation) when the CRTC has either an applied binding **or** an in-flight record whose `prior` still owns a binding. An accepted nonblocking hide sets `applied = None` before its event; in that case use the in-flight `prior.properties.plane` for the blocking detach. For a replacement in flight, use the applied plane and settle both applied and prior ownership. Submit the detach even when an ID-tagged nonblocking commit is in flight (the kernel serializes a blocking commit behind it; skipping it can leave the plane attached through the CRTC disable). A successful blocking atomic commit returns after the hardware has stopped using those framebuffers, so release the applied lease and any **distinct** in-flight prior lease; if `prior` aliases the applied lease for the same CRTC, release that user only once. Set any released `prior = None`. A failed detach keeps the applied binding and every lease, marks the comparison invalid (`valid = false`), and follows the existing error path. There is no lifecycle-pending owner. `resume_visible` records a binding that was detached so resume re-attaches; if detach failed, `hw_bound_on` still selects the retained applied binding for resume.

The release-at-return rule is verified for the in-tree DRM atomic-helper path: `DRM_IOCTL_MODE_ATOMIC` with `nonblock == false` runs commit-tail synchronously, waits for the relevant active CRTC hardware completion, then cleans up planes; the legacy-cursor exception that skips these waits is not used by this ioctl. Inactive CRTCs do not scan out. NVIDIA's out-of-tree implementation cannot be established from that source review, so the Task 6 lifecycle run observes framebuffer release on NVIDIA as well.

**R23 — Invalidation keeps live ownership; every removal route has a release owner.** VT/DRM-master loss, resume, modeset and DPMS-on mark the comparison invalid (`valid = false`) without releasing a live CRTC's lease; the next cursor commit on such a CRTC sends the full state. In-flight `Atomic` records are removed by their event (R11), by R22 (their prior), by `clear_atomic_cursor_state_after_old_events_discard` (releases the prior of a record whose event was discarded), or by cleanup of the removed CRTC. Every output removal route calls the same CRTC ownership cleanup after a successful all-off: explicit disable/removal through `remove_connector_at` (including Backend RANDR's `remove_connector_after_all_off`) and physical removal in `apply_connector_snapshot` (after `run_display_rescan` or resume has quiesced and disabled the old topology). Cleanup releases the removed CRTC's unique applied/in-flight lease ownership once, then removes only that CRTC's state and record; live CRTCs on the device keep their ownership for rebind. A refresh never keeps leases of a removed CRTC and never drops those of a live one. On shutdown, after each successful output disable, settle any lease in an in-flight hide's `prior`, release remaining unique ownership for that disabled CRTC, and remove its state/record; this teardown does not wait for an old cursor event. Since #273, physical removal in `apply_connector_snapshot` covers only a connected connector that advertises no usable mode; a physically disconnected output keeps its route, CRTC and cursor ownership. Shutdown first clears each device in one blocking all-off commit; for a device so cleared it skips the per-output detach and disable and settles every CRTC of that device right after the clear. The VT resume device-wide clear settles nothing: the suspend detach already released, or a failed detach keeps the binding for the resume rebind. The sprite pool's maximum is updated from the active CRTC count at every refresh and never shrinks below the number of buffers it already holds.

**R24 — Assignment is fixed in P2.** The CRTC-to-plane assignment and `properties_by_crtc` are computed once in `CursorPlane` construction and are immutable for the plane's lifetime; P2 introduces no re-probe (a refresh calls `retain_crtcs` and recomputes only availability gates). Moving a bound plane between CRTCs, re-probing topology, deferred detach riding a frame, transfers and quarantine are P5.

**R25 — Legacy is bit-for-bit master, with one stated exception.** With `CursorStatePath::Legacy` no sprite buffer is allocated, no `AddFB2` or cursor-plane property other than master's `CRTC_X`/`CRTC_Y` is issued, `upload`/`show`/`hide`/`move` take master's code paths, and every existing master cursor test passes unmodified except for mechanical signature updates (the sink method names of R19 and the retire argument of R11). The exception: once R1's cursor step is wired (P2b Task 5), a paravirtualized device whose kernel accepts the hotspot capability stops having its cursor planes hidden by the kernel; if it still decides `Legacy` for another reason it now sees cursor planes, gets an explicit assignment and may become `topology_blocked`, where master saw zero planes and took the optimistic probe. This is accepted: on kernels >= 6.8 such devices otherwise expose no cursor plane at all (they take master's no-plane path), and on older kernels the capability returns `EINVAL` and nothing changes.

## Eligibility decision table

Evaluated once, at `CursorPlane` construction, over the assignment computed then. First matching row wins. The permanent latch (`permanently_disabled` after `ENXIO`/`ENODEV`/`EOPNOTSUPP`) and `topology_blocked` are device availability state, not part of the path.

| # | Condition | Path | Cursor result |
|---|-----------|------|---------------|
| 1 | No cursor plane exposed or none assigned (Apple DCP, headless; paravirtualized devices on kernels >= 6.8 without the capability) | Legacy `no-cursor-plane` | Optimistic legacy probe; software on first `ENXIO` (master) |
| 2 | Device caps were not negotiated (`cursor_caps() == None`) | Legacy `no-device-caps` | Master behavior |
| 3 | Any assigned plane lacks one of the ten required properties | Legacy `missing-property:<NAME>` | Master: legacy bind, position-only atomic where `CRTC_X`/`CRTC_Y` exist |
| 4 | Driver paravirtualized or unknown, and (capability rejected or any assigned plane lacks `HOTSPOT_X`/`HOTSPOT_Y`) | Legacy `hotspot-support-missing` | Master behavior (the legacy ioctl carries the hotspot). Matters only on kernels < 6.8 |
| 5 | Otherwise (physical driver with the ten properties, or paravirtualized with accepted capability and both hotspot properties) | **Atomic** | Hardware cursor via full-state commits |

A physical driver that rejects the hotspot capability is *not* demoted by that rejection (row 5 applies). A CRTC with no assigned plane on an Atomic device stays on master's `topology_blocked` software gate.

## Sprite and lease lifetime

For one CRTC `C` and sprites `F0` (applied) and `F1` (replacement):

1. `stage(F1)` writes a free buffer; no user is added. If none is free the call returns `Deferred` and `F0` stays untouched (R8).
2. `reserve(F1)` before `submit_with_commit_id`. A failed submit rejects the reservation: `F0` remains the only owner, `F1` is free again, nothing is in flight.
3. A successful submit with ID `k` accepts the reservation: `F1` gains a user, `applied = F1`, `in_flight = { id: k, prior: F0 }`. `F0` still has its user (R10).
4. The event carrying `k` for `C` on this device retires `in_flight`: `F0` loses its user and, if it has none left on any CRTC, becomes free for the next write or `RMFB`.
5. A detach commit with ID `k` follows the same steps with `next = None`; its event releases the former binding.
6. A blocking detach (R14, R22) has no event: on success it releases the applied binding and the in-flight record's prior immediately (the record's `prior` becomes `None`, so its later event releases nothing twice).

An event whose ID is not `k` performs none of step 4's releases (through `Backend` such an event is dropped earlier by P1; a zero cookie retires the pending replacement by FIFO exactly once). Two CRTCs showing the same sprite hold two users and release at their own replacing events; the buffer is reusable only after both.

## Expected cost

Image, hotspot, attach and detach changes are cursor-only commits, each occupying the CRTC's single commit slot for one vblank; the next scene commit is gated by `cursor_commit_in_flight_for_output` and a direct successor by `cursor_commit_in_flight_for_outputs`. Until P3 moves these changes onto the frame commit, an animated cursor can cost up to one scene frame per animation frame, and in held direct scanout a show that is deferred because a commit is in flight is treated as a hook failure (as master treats its errors), taking the existing unflip path, so an animated cursor over a fullscreen direct client can cause repeated unflips. Master's legacy ioctls do neither. This is accepted for P2, measured on hardware against master (the matrix cases above), and not "fixed" here by new scheduling.

## Non-goals

- Frame receipts, frame-owned HW/SW handoffs, late sampling, removal of `ShowOnRetire`/`HideOnRetire` and of stored retire-time coordinates, the cursor-jump fix (P3).
- AMD scheduling suppression, the output-local cursor gate, one-attempt-per-pass latches, persistent deferred-upload eligibility, request-backlog reporting (P4).
- Rejection recovery beyond master's policy and the minimum-safety blocking detach of R14: explicit-detach `DetachPending`/`RetainHardware` states, qualification keys and epochs, retry-per-key, cursor-only retry, EBUSY/EINVAL attribution changes, `CursorlessReplacement`, plane reassignment or re-probe, quarantine, legacy executor and fallback-state removal, `shutdown_outputs`, the check-layout cursor guard (P5).
- The four maintainer findings (deadline spin in `scanout.rs` is P4; "only EINVAL blames the cursor" is P5; the zero-CRTC cookie fallback was closed in P1; the guard is P5).
- Scene, direct, copied or unflip commits carrying anything other than a position delta; any change to `drm/modeset.rs` disable commits (the lifecycle detach is a separate blocking commit, R22).
- `KmsServices` and the reference's large `round_*` fixtures; a per-CRTC mixed path on one device; gamma/LUT, overlay planes, scaling, new cursor protocol features.

## Test requirements

**A - End state.** Every stateful scenario asserts intermediate retention (the old lease still has its user between acceptance and the replacing event) and a final settled state through normal completion: no sink pending-flip entry (`for_tests_pending_page_flip_entry_count() == 0`), no in-flight cursor record, no reserved or accepted sprite user, no live dumb buffer, mapping or framebuffer in the cursor ledger after pool release, no unsent intent. Use `assert_no_cursor_resources` after `finish_fixture`; destroying a fixture or clearing a map is not evidence of settlement. The shutdown regression deliberately withholds an accepted hide event after a successful blocking detach and shutdown disable; it asserts cursor state/leases/reservations and ledger are settled after pool drop but does not claim the generic P1 event association was retired or call `finish_fixture`.

**B - Production drivers.** Lifecycle tests install topology, a recording buffer I/O, a recording atomic executor and P1's device-qualified explicit-cookie injector (`AtomicEventFixture::queue_commit_completion`, `accepted_event_id`) and then advance only through `Backend` trait entries (`define_cursor`, `warp_pointer_root`, `clear_area`, `maybe_composite`, `try_present_direct`, `on_page_flip_ready`, `on_scanout_render_completion`, `set_cursor_hidden`, DPMS/VT entries, `disable_output`) or `core_loop::run_core`. Never call `submit_atomic_cursor_intent_for_output`, `accept_cursor_commit`, `retire_*`, or lease methods to fake a production path. Pure boundary tests (the sprite pool algorithm, the `prepare_cursor_commit` truth table, capability/path decisions, request tagging, the scene crate's pure functions, and the retirement equality check on a constructed in-flight record) call their functions directly, say so, and are the only tests allowed to call `retire_*` or lease methods; they do not substitute for the Backend-driven scenarios.

**C - Hardware.** A separate final coordinator task runs `tools/cursor-bench` master versus branch on AMD (`card0`) and NVIDIA (`card1`). It needs the user's authorization at that time (the 2026-10-19 unattended authorization covers P1 only) and a check for GPU clients before each run. The matrix adds a scene-frame-rate case under an animated cursor, an animated cursor over a fullscreen direct client, a connector disable/re-enable x3 lease check, and NVIDIA lifecycle framebuffer-release observation because its driver is out of tree. Paravirtualized-driver (virtio-gpu, kernel >= 6.8) validation is listed as pending unless a VM is available.

**F - Repetition and skips.** Every new test runs 5 times under 16 busy loops; every test that waits on GPU work runs 20 times. Every fixture skip prints exactly one line naming its reason, emitted by the deciding constructor (for example missing Vulkan or SYNC_FD). Each planned test names the production mutation that must make it fail at its named assertion (not at a build error or timeout).
